# 舰船与水域单位纸面设计

状态：`PAPER-ONLY-NAVAL`。本切片只保留未来接口，不实装任何可生产、可选择、可战斗的舰船单位。

## 设计目的

舰船不是“地面坦克换皮”。它们应该服务于地图控制和路线压迫：水域提供侧翼、运输、远程火力和资源争夺，但不能抢走地面主战场的清晰度。现在的 1v1 纵切目标仍然是狗狗与猫猫的陆空战斗，所以海军只做纸面设计。

## 未来移动域

`MovementDomain.Naval` 只允许在水面和近岸航道移动，不能穿越普通地面。

`MovementDomain.Amphibious` 可以从地面进入浅水或海岸，但速度、转向和碰撞半径都应明显不同，避免变成万能单位。

水域寻路应该独立于地面拥堵。未来如果实现大规模舰队，优先使用共享航道或流场，而不是逐舰 A*。

## 读图规则

舰船必须在一秒内读出“这是水上单位”。视觉上需要满足：

- 细长船体或浮台比例，不能像坦克。
- 船体下方有软阴影或水面压痕。
- 移动时生成低对比度尾波，尾波是表现层效果，不进入模拟。
- 舰炮或甲板模块可以旋转，但船体转向应更慢。

## 未来单位方向

轻型巡逻艇：T1/T2 之间的快速视野与骚扰单位，低血量，高速度，只能压制轻甲和采集路线。

防空护卫艇：水域防空锚点，保护舰队不被飞机免费打掉，但对地输出有限。

岸轰平台：慢速远程单位，压制建筑和防线，需要视野与护航。

两栖工程艇：未来战役或地图机制单位，用于修复桥梁、灯塔、水闸或中立码头。

运输艇：未来多人或大地图功能，不进入当前 1v1 纵切。

## 阵营差异

狗狗舰船应该更稳、更厚、更像守护用的移动码头，轮廓宽，甲板清楚，贴纸区域可以放在船首护板或侧舷条带上。

猫猫舰船应该更轻、更窄、更像安静穿行的月光艇，轮廓锋利，尾波细，贴纸区域可以放在帆片、船脊或侧翼小徽记上。

第三阵营舰船暂不设计实装，只保留“污染水面、扭曲航道、制造压力”的方向。

当前生产 UI 可以保留灰色海军入口作为未来提示，但不能接入真实生产队列。

当前平衡报告不应包含海军战斗场景。

当前 `EntityWorld` 可以保留 `MovementDomain.Naval`、`MovementDomain.Amphibious`、`ArmorTag.Ship` 等未来枚举，但这些不能对应实际可生产单位。
