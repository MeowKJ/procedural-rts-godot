# Git 规范

本文档定义本仓库的 Git 使用约定，重点规范 commit message，方便后续检索、回滚、生成变更记录和多人协作。

## Commit 格式

所有提交标题使用以下格式：

```text
英文前缀(模块): 中文说明
```

冒号使用半角 `:`，冒号后保留一个空格。前半段保持英文/ASCII 结构，便于脚本、commitlint、自动 changelog 等工具解析；后半段使用中文说明，便于团队阅读。

示例：

```text
feat(core): 增加单位生产队列快照
fix(ui): 修复暂停菜单按钮状态不同步
refactor(world): 整理战争迷雾渲染层职责
docs(git): 补充提交信息规范
test(tools): 增加战斗行为冒烟验证
```

## 英文前缀

| 前缀 | 使用场景 |
| --- | --- |
| `feat` | 新功能、新玩法、新系统能力 |
| `fix` | 修复 bug、错误行为、崩溃、状态异常 |
| `refactor` | 不改变外部行为的代码重构 |
| `perf` | 性能优化、减少分配、降低渲染或模拟开销 |
| `test` | 新增或调整测试、QA 工具、验证脚本 |
| `docs` | 文档、设计说明、规范文件 |
| `style` | 仅格式、命名、排版调整，不改变逻辑 |
| `build` | 构建、导出、依赖、项目配置 |
| `chore` | 仓库维护、清理、杂项工作 |
| `revert` | 回滚历史提交 |

## 模块命名

模块使用英文小写，优先选择能定位改动范围的目录、系统或功能名。

常用模块：

| 模块 | 范围 |
| --- | --- |
| `core` | 核心模拟、数据结构、规则计算 |
| `sim` | ECS/模拟系统、时钟、事件、不变量 |
| `units` | 单位定义、阵营单位、运行时单位系统 |
| `ui` | HUD、菜单、设置、提示层 |
| `world` | 世界视图、网格、战争迷雾、特效层 |
| `controllers` | 输入、选择、镜头、生产、建造控制器 |
| `scenes` | Godot 场景文件 |
| `tools` | 命令行验证工具、QA 脚本 |
| `assets` | 图标、美术、音频等资源 |
| `docs` | 普通项目文档 |
| `git` | Git 规范、忽略规则、仓库维护 |
| `build` | Godot 导出、.NET 构建、工程配置 |

如果一次提交涉及多个模块，优先选择主要受影响模块；确实横跨全局时使用 `project`。

## 中文说明

中文说明使用一句简短动宾短语，描述“做了什么”，不要写过程。

推荐：

```text
feat(units): 增加猫阵营火箭兵定义
fix(core): 修复建造半径边界判断
perf(world): 缓存网格可见区域计算
```

不推荐：

```text
update
修复 bug
feat: 改了一些东西
feat(core): fix stuff
```

## 提交正文

简单提交只写标题即可。复杂提交可以增加正文，说明原因、风险、验证方式或兼容性影响。

```text
refactor(sim): 拆分生产系统完成事件

将队列推进和完成事件派发分离，便于后续接入建筑生产 UI。
验证：dotnet build .\ProceduralRts.csproj
```

## 提交前检查

提交前至少检查：

```powershell
git status --short
```

修改 C# 代码时建议运行：

```powershell
dotnet build .\ProceduralRts.csproj
```

不要提交以下内容：

- `.godot/`、`bin/`、`obj/` 等生成目录
- `artifacts/`、截图、录屏、QA 输出
- 本地 IDE 配置和个人助手配置
- 临时日志、导出包、系统缓存文件

## 推荐提交粒度

一个 commit 只做一件明确的事。优先让每个提交可以独立理解、独立回滚、独立验证。

可以拆分：

```text
feat(core): 增加单位护甲标签
feat(ui): 在选择面板显示护甲标签
test(tools): 补充单位护甲克制验证
```

不建议把无关改动混在一起：

```text
feat(project): 增加护甲系统并修改菜单样式和清理文档
```
